## Challenge

Start on a Claude subscription, but never be locked in to one vendor: experimenting with many models
and tools (including OpenRouter) is part of the learning.

## Context

Agent CLIs keep their memory in vendor-specific sessions. A factory that relies on that memory can't
switch models halfway through a run.

## Options

- Use one vendor's SDK and abstract later.
- Keep all state in files and git, and call each agent CLI through a thin adapter.

## Decision

State outside the agent (spec, tasks, progress, ledger in files and git); a fresh session per task;
a small adapter per CLI (`claude-code`, `opencode` in v0); agents chosen per role in `factory.yaml`.
Bonus: the reviewer can run on a different vendor from the implementer, a cheap guard against an
agent grading its own homework.

## Result

Pending: v0 success criterion 2 (the same brief built with a different agent or model for at least
one role).

## Lessons

Vendor independence is mostly a memory problem. Put the memory where every agent can read it.
